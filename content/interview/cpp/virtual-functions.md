「虚函数怎么实现的？」几乎是 C++ 面试的开场白。背下「虚表」两个字不够——追问往往在对象内存布局和构造顺序上。

## 虚表与虚指针

每个**有虚函数的类**对应一张虚表（vtable）：一个函数指针数组，编译期生成，整个类共享一张。每个**对象**头部藏一个虚指针（vptr），指向所属类的虚表——这是对象因虚函数付出的空间代价（一个指针，64 位下 8 字节）。

调用 `p->foo()` 时：取 `p` 的 vptr → 找到虚表 → 按 `foo` 在表中的固定下标取函数指针 → 调用。两次间接寻址，这就是虚函数的运行时开销来源（以及它阻碍内联的原因）。

::::card{id=cpp-vtable-basics}
C++ 虚函数调用的完整过程是什么？开销在哪？

:::answer
1. 从对象头部取出 vptr（每个对象一个，指向其类的虚表）
2. 按该虚函数在虚表里的**编译期固定下标**取出函数指针
3. 间接调用

开销：两次额外的内存访问（取 vptr、取函数指针）+ **无法内联**（编译期不知道调哪个实现）。后者在热路径上往往比间接寻址本身更伤性能。

空间代价：每对象一个 vptr（8 字节），每类一张虚表。
:::
::::

## 构造函数里调用虚函数会怎样？

调用的是**当前构造层级的版本**，不是最终派生类的。因为基类构造运行时，vptr 指向的还是基类虚表——派生类部分尚未构造，动态绑定到它是未定义行为的温床，所以 C++ 干脆在构造期间就地绑定。

::::card{id=cpp-ctor-virtual}
在基类构造函数里调用虚函数，会调到派生类的重写版本吗？为什么？

:::answer
**不会**，调用的是基类自己的版本。

对象构造是「由基到派生」逐层进行的：基类构造函数运行时，vptr 被设置为指向**基类**的虚表，派生类部分还不存在。此时若绑定到派生类实现，它访问的成员都未初始化——所以语言规定构造/析构期间虚函数按当前层级静态解析。

析构同理（由派生到基，反向）。这也是「不要在构造/析构里调虚函数」这条戒律的真正原因——不是不能调，是调了不是你以为的那个。
:::
::::

## 为什么析构函数常要声明为 virtual？

`delete basePtr` 时若析构非虚，只会执行基类析构——派生类的资源泄漏。规则：**类要被多态使用（通过基类指针 delete），析构必须 virtual**；反之（如纯工具基类、CRTP）不需要，省下 vptr。

::::card{id=cpp-virtual-dtor}
什么时候基类析构函数必须是 virtual 的？不是 virtual 会怎样？

:::answer
当对象会**通过基类指针被 delete** 时（多态使用），析构必须 virtual。

非虚时 `delete basePtr` 是静态绑定——只调用基类析构，派生类的析构不执行，其成员持有的资源（内存、句柄、锁）全部泄漏。这是未定义行为，不只是泄漏。

反例：不打算多态删除的基类（策略类、CRTP 基类）不需要虚析构，还能省掉整个 vtable。`std::vector` 等标准容器没有虚析构，就是明确告诉你别继承它当多态基类用。
:::
